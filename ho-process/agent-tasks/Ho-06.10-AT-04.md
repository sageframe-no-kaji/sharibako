**Required Changes**

1. **Unprotect** (`requestUnprotectSelectedProject()` → confirm →
   `confirmUnprotect() async`). Steps, in order, all on the worker after
   one key acquisition: `materialize(marker:overwriteDrift:false)` — if it
   reports a pending diff, stop and show the drift dialog as Write .env
   would (the user resolves, then Unprotect again); `deleteScope`; remove
   the claim file; refresh scopes + scan + candidates; the folder appears
   under Not protected and is selected. Announce "Unprotected bento — 3
   secrets are back in .env in plain text." The confirmation names exactly
   that consequence. Rust verb in the action column for `.project` rows
   with a folder; disabled with reason for no-folder projects ("No folder on
   this Mac to write the values into").
2. **After-the-fact shared** on a protected line (`SecretDetail` +
   context menu): **Use shared secret…** → a picker of `sharedIDs`
   (`VaultCore.link`; the local value is replaced by the link — the
   confirmation says "‹KEY› will use the shared secret ‹id› from now on; its
   own value is discarded"). **Make it a shared secret** → a name field
   defaulting to the key lowercased with `_` → `-` (`addSharedEntry` with
   the decrypted local value, then `link`), one Touch ID. Both refresh
   `linkGraph` and the shared section.
3. **Check all.** Iterate every project with a folder; catch per project;
   accumulate `checked`, `outOfDate`, `unreadable: [scopeID: message]`;
   never abort the sweep on one failure. Announce "4 checked · 1 out of
   date · 2 could not be read". Unreadable projects get a `paneError` when
   selected ("This key cannot read these secrets… Next: Unprotect is not
   possible without the key; Delete project and protect the folder again,
   or switch to the key that made it"). **Value match:** for each protected
   local line decrypted during the sweep, compare against each shared
   secret's value (`getSharedValue`, decrypted once per sweep); matches are
   stored as `sharedMatches: [scopeID: [key: sharedID]]`, rendered on the
   line's caption ("same value as shared ‹id›") and offered as "Use shared
   secret ‹id›" in its detail and context menu.
4. **Remote…** (VAULT): a sheet with the current remote (or "No remote"),
   a text field, Save → `Conduit.setRemote` (validation as the wizard's
   remote page), Remove → unset (`git remote remove origin` via a small
   Conduit addition if none exists — say so). Footer updates. Announce.
5. **Scan folders…** (VAULT): a sheet listing `scanRoots` with full paths,
   **Add…** (NSOpenPanel, directories) and **Remove** per row; persisted via
   `WorkshopConfig.persistScanRoots(_:configURL:)`; closing the sheet runs
   `rescan()`. The footer's roots line reflects the change. Empty list
   state: "No folders are scanned yet. Add the folder where you keep your
   projects."
6. **Errors in the pane.** Every intent that today sets only
   `errorMessage` for a selected project or line also sets `paneError`
   (message + a next step where one exists: key mismatch → the sentence in
   item 3; markerNotFound → "Attach a folder with Scan folders… or protect
   the folder again"; git push rejected → "Pull on the other machine, then
   Sync again"). `paneError` clears on selection change and on the next
   successful action. `SecretDetail`, `LineDetail`, and `ProjectPage` render
   it where AT-03 placed it.
7. **Words.** Ten words plus Decision 7's labels; no new jargon.
