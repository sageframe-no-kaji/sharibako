**Required Changes**

1. **Header mark size.** The status symbol in the header is the same size as
   the row glyphs' big sibling: 20 pt, not 28; red octagon and green check
   alike. The state row reads as one line with the label.
2. **Header words** (`ProjectHeaderState.label`, tested):
   - no protected lines, N unprotected secrets → "Project not protected —
     N secrets in plain text" (singular handled);
   - some protected, N unprotected → "N secrets not protected";
   - all secrets protected → "Protected" (+ up-to-date clause as today);
   - only settings, nothing protected → new case `.nothingToProtect(settings:
     Int)` → "No secrets to protect — N settings in .env"; `offersProtect`
     false; symbol `minus.circle` in `inkTertiary`.
3. **Settings-only folder in the sidebar.** `ProjectStatus` gains
   `.noSecrets` (symbol `minus.circle`, `inkTertiary`, label "No secrets",
   help "No secrets to protect — only settings in .env"). A candidate whose
   `.env` classifies to settings only takes it; it stays listed under Not
   protected (it is still not in the vault) but `Protect all` skips it and
   its Protect verb is disabled with the reason "No secrets to protect".
   The decision needs the folder's lines, which the sidebar derivation does
   not have: add a lightweight keyless classification pass over `candidates`
   in the same worker hop as the candidate scan (`EnvReader` is
   off-main-safe), cached as `candidateSummaries: [URL: (secrets: Int,
   settings: Int)]`; the sidebar reads it. Tested.
4. **Recommendation made explicit.** Every unprotected or setting line
   carries a visible tag in the row's caption: "Recommended: protect" (for
   a secret-class line) or "Recommended: leave as setting", followed by the
   reason ("key ends in KEY"). In `LineDetail`, the recommended choice's
   title ends with " (recommended)". `lineCaption(for:)` and
   `lineChoiceTitle(_:)` own this, tested.
5. **Make it a shared secret: a popover, not an inline form.** From the
   right-click menu and from `SecretDetail`, the name form presents as a
   `.popover` anchored to the invoking row or button (`lineShareForm` state
   already exists; add an anchor id), with the suggested name, the
   validation note, and the one button. It never renders beneath the detail
   pane's sections. The same for "Use shared secret…" when it needs a
   picker.
6. **Blank page bug.** Repro: select a protected project, right-click a
   line → Make it a shared secret → confirm; then click an empty area of the
   lines list (deselecting the line). Both content and detail columns go
   blank; the toolbar title stays. Find the cause — the suspects are
   `areLinesLoaded` (`loadedLinesSelection == selection`) going false after
   the post-change `loadScopes()` without the window's `.task(id:
   model.selection)` re-running (selection unchanged), or `selectedEntry`
   resolving to nil mid-refresh. Fix at the model level so that any refresh
   that invalidates the lines also reloads them for the current selection
   (`loadContent(for: selection)`), and the page never renders an empty
   body: while lines are reloading it shows the header and "Reading…" in the
   list area. Add a test that reproduces the sequence headlessly and asserts
   `areLinesLoaded` is true afterwards.
7. **Value match at Protect time.** Inside `ProjectProtector.protect` (the
   key is already in hand), before committing: for each line whose choice is
   `protectLocal`, compare its plaintext value with every shared secret's
   value (`VaultCore.getSharedValue`, decrypted once per protect). If any
   match, do not commit; return a `SharedValueMatches` result
   (`[(key, sharedID)]`). The model surfaces it as a confirmation dialog:
   title "Some values are already shared secrets", message listing
   "OPENAI_API_KEY has the same value as the shared secret openai-api-key"
   per match, buttons **Use the shared secrets** (flip those lines to
   `useShared` and commit) and **Protect separately** (commit as planned).
   Read the pending matches synchronously in the button action (the dialog
   dismissal clears pending state first). Applies to `protectLine`,
   `protectRecommended`, and per project inside `protectAllCandidates`
   (which asks once per project with matches). Tested with a temp vault,
   an ephemeral key, a shared secret, and a line sharing its value.
