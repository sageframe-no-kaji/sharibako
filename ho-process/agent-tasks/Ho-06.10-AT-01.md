# Ho-06.10-AT-01 — `SecretClassifier` in Core; CLI `init` defaults

**Goal**

Add the secret-or-setting classification rule to `SharibakoCore` as a pure,
tested type, and make CLI `init` use it for its defaults: every detected
line is shown with its class before the prompt, the one-key default protects
the secrets and leaves the settings alone, and `--yes` prints each line's
class because scripts cannot look. The rule only sets defaults; the user can
override any line. No GUI changes in this task.

**Context**

`ho-process/hos/ho-06.10-protect.md` Decisions 1–3 (the rule is spelled out
there, in order; follow it exactly, including the amended fallback: anything
not recognised as a plain setting is a secret). kamae-2.3 §4 for the
origin. Read `Sources/SharibakoCore/MaterializerTypes.swift` (`ProposedScope`,
`DetectedKey` with `key`, `value`, `sourceFile`, `nameMatchedSharedID`;
`KeyDecision`), `Sources/SharibakoCLI/Commands/InitCommand.swift`,
`Sources/SharibakoCLI/Support/PlainIngestPrompt.swift` (the interactive
decisions; "Import all N as scope-local? [Y/n]" is the line that changes),
`Support/ScriptedIngestDecisionSource.swift` and
`Support/IngestDecisionSource.swift` (the non-interactive path), and the
tests `Tests/SharibakoCLITests/PlainIngestPromptTests.swift`,
`PlainIngestPromptDefaultsTests.swift`, `InitCommandTests.swift`,
`IngestDecisionSourceTests.swift`.

**Files**

- Add: `Sources/SharibakoCore/SecretClassifier.swift` — `public enum
  LineClass: Sendable, Equatable { case secret(ClassificationReason),
  setting(ClassificationReason) }`, `public enum ClassificationReason:
  String, Sendable, CaseIterable` (one case per rule arm, with a
  `public var explanation: String` in plain words, e.g. "key ends in
  _SECRET", "looks like a port number", "URL carries a username and
  password", "not recognised as a plain setting"), `public enum
  SecretClassifier { public static func classify(key: String, value:
  String, nameMatchedSharedID: String?) -> LineClass }`, and `public
  extension ProposedScope { func classifiedKeys() -> [(key: DetectedKey,
  lineClass: LineClass)] }` (or a small `ClassifiedKey` struct if tuples
  fight `Sendable`).
- Modify: `Sources/SharibakoCLI/Support/PlainIngestPrompt.swift` — the key
  list prints each line as `[secret]` / `[setting]` with the reason in
  parentheses; the bulk question becomes "Protect N secret(s) and leave M
  setting(s) alone? [Y/n]" (zero-aware: "Protect 3 secrets? [Y/n]" when M
  is 0; "Leave all 2 settings alone? [Y/n]" when N is 0); accepting applies
  `.importAsLocal` to secrets and `.leaveAlone` to settings; declining
  falls into today's per-key override flow with the class shown per key
  and the per-key default from the class.
- Modify: the non-interactive decision source so `--yes` / non-TTY applies
  the class defaults and prints one line per key: `PROTECT  KEY  (reason)`
  or `LEAVE    KEY  (reason)` to stdout before committing. Find where the
  current non-interactive default (import-all) lives and replace it; keep
  the scripted-decision fixture path working for tests.
- Add tests: `Tests/SharibakoCoreTests/SecretClassifierTests.swift` — a
  corpus of at least 40 lines, each asserting class AND reason, covering
  every rule arm in Decision 2 with at least two examples per arm,
  including: `OPENAI_API_KEY=sk-…`, `JWT_SECRET=…`, `AWS_ACCESS_KEY_ID=…`,
  `DATABASE_URL=postgres://u:p@h/db` (secret), `DATABASE_URL=postgres://localhost/db`
  (setting), `REDIS_URL=redis://cache:6379` (setting),
  `CONTACT_FORM_WEBHOOK=https://hooks.example/abc` (secret by key),
  `PORT=3000`, `DEBUG=true`, `NODE_ENV=development`, `LOG_LEVEL=info`,
  `DETECTION_THRESHOLD=0.85`, `OUTPUT_DIR=/Users/x/Audiobooks`,
  `CACHE_DIR=./tmp`, `API_HOST=localhost`, `ENABLE_BETA_ROOMS=false`,
  `EMPTY=`, `CLOUDFLARE_ACCOUNT_ID=<32 hex>` (secret by fallback),
  `SESSION_COOKIE_NAME=sid` (setting, enum-looking), a PEM value (secret), a
  JWT value (secret), a shared name match (secret, `sharedNameMatch`).
- Update tests in `Tests/SharibakoCLITests/` for the new prompt text and
  defaults; add a test that `--yes` output lists every key with its class.

**Required Changes**

1. The classifier is pure, has no dependencies beyond Foundation, and is
   documented rule by rule in its DocC comment with the order stated.
2. Rule order and arms exactly as Decision 2. The key-shape suffix check
   uses the uppercased key and treats `_` as optional before the suffix
   (`APIKEY`, `API_KEY`, `SECRETKEY` all match).
3. The "enum-looking word" arm must not swallow secrets: it applies only
   when rules 1–3 did not fire and the value is at most 24 characters of
   `[A-Za-z0-9_-]` **and** contains no digit run of 6 or more.
4. Hostname arm: `[a-z0-9.-]+(:\d+)?` with no scheme, no `@`, no `/`.
5. URL arm (setting): has a scheme, no user info, no `?`; a URL with a
   query string or user info is a secret (rule 3 / fallback).
6. CLI output under `--yes` goes to stdout, one key per line, before the
   commit summary; the existing JSON output mode (if `init` has one) is
   left unchanged or gains a `class` field — read the code and pick the
   smaller change; say which.
7. Nothing in `Sources/Sharibako/` changes.
