# ho-06.9 — The projects surface

The first build ho of the kamae-2.3 arc. The Workshop stops being a window
onto the vault (scopes grouped by type) and becomes a list of the user's
projects, each with a status, each status with a home and its verbs. The
"seen but not yet protected" state, which today exists only inside a modal
chooser, becomes a persistent section at the top of the sidebar. The action
column becomes contextual. The shared pool gets a section. Everything this
ho touches is born in the ten words; the sweep of older strings is ho-06.11.

**Zero `SharibakoCore` / `SharibakoCLI` changes.** Every engine operation this
surface needs exists: `scan`, `ingest` (keyless proposal), `acceptIngest`,
`listShared`, `linkGraph`, `heal`, `materialize`. ho-06.10 brings the one
Core change of the arc (the classification rule); it is not here.

**Out of scope:** bulk protect and the classification rule (06.10); the
vocabulary sweep of `SecretDetail`, `SecretList`, the Add windows, the CLI
(06.11); per-project up-to-date check on selection (06.11); multi-root
management (06.6); any shared-secret editing, linking, or rotation (ho-07).

**The gate** is not a script. The practitioner uses the app against the
sandbox vault and tries to break it. The build session's own gate is the
scripted sandbox walk (`docs/screenshots/CAPTURE.md`) with every frame read
back, plus the three jobs narrated from the screenshots.

## Phase 1 — Think

Decisions ratified in kamae-2.3 are not re-decided here. These are the
execution-level calls, logged from the codebase.

### Decision 1 — One selection, four kinds

`WorkshopModel.selection: Selection?` replaces `selectedScopeID` as the
sidebar's binding. `Selection` is an enum: `.project(scopeID)`,
`.candidate(URL)`, `.problem(markerPath)`, `.shared(id)`. `selectedScopeID`
stays as a computed property (get: the `.project` case; set: assigns
`.project` or `nil`) so every existing intent, view, and test keeps working;
its `didSet` cascade (clear secret, revealed value, caches) moves to
`selection`'s `didSet`. The List tags rows with a `Hashable` row ID that maps
one-to-one onto `Selection`.

### Decision 2 — Project entries are derived, never stored

`ProjectEntry` (name, directory, scopeID, status) and `ProjectStatus`
(`notProtected`, `protected`, `outOfDate(keyCount)`, `problem(UnlinkedMarker)`,
`noFolderHere`) are computed from four existing caches: `scopes`,
`scanReport`, `driftReports`, and a new `candidates: [URL]` cache. Nothing is
persisted; the same posture as `scanReport`. The sidebar reads
`projectSections` and renders. Section order is fixed: Not protected,
Projects, Needs attention, Shared secrets. Empty sections are omitted, except
that an entirely empty vault with no candidates shows one empty state.

### Decision 3 — Candidates join the launch scan

`performLaunchScan()` and `rescan()` run `IngestCandidateScanner
.findUnboundCandidates(under:)` in the same worker hop as the marker scan and
store the result in `candidates`. A successful Protect removes its directory
from `candidates` and splices the marker (as today). A successful Forget
re-runs the quiet scan so the folder reappears under Not protected if it has a
`.env`. Rescan's status line becomes "Found N projects to protect; M already
protected." (zero-aware).

### Decision 4 — The window opens where the work is

When the launch scan finishes and nothing is selected: select the first
Not-protected row if there is one, else the first project, else nothing.
After a Protect commits, select the newly protected project. Tested.

### Decision 5 — The chooser is retired

`IngestChooserSheet`, `presentIngestChooser`, `selectIngestCandidate`,
`dismissIngestChooser`, `IngestState.candidates`, `offerFirstRunIngestInvite`,
and the `chainOnCommit` behaviour are deleted; so are their tests, replaced by
tests of Decisions 2–4. The first-run finish page keeps its preview
(`findFirstRunIngestCandidates`) but its copy becomes "Found N projects with a
.env — they'll be waiting under Not protected." and the button is always
"Create Vault". The wizard hands off into a window that already opens on the
first candidate (Decision 4).

### Decision 6 — The Protect verb reuses the ingest sheet, reworded

`beginIngest(directory:)` and `IngestSheet` are kept as the per-project
Protect flow in this ho. The sheet's title becomes "Protect <name>", the
commit button "Protect", the activity label "Protecting…", the count line
"N lines found". The verdict labels and the Scope ID / Scope type fields stay
until 06.10 replaces this sheet with the review screen. Entry points: the
Protect button on the Not-protected page, the Protect verb in the action
column, and "Protect this folder" on a Problem page (seeded, as today's
`createScopeFromMarker`).

### Decision 7 — Contextual action column

`ActionPanel` renders three groups: the selection group, titled with the
selected thing's name (verbs by kind, below); VAULT (Rescan, Sync, Check all,
Write all out of date — the last enabled only when the drift cache holds a
drifted project); and one **New…** menu button holding New project (the Add
Scope window), New secret (the Add Secret window, enabled on a project
selection), New shared secret (the Add Shared Secret window). Appearance
stays at the base. Ingest Project… is gone.

| Selection | Verbs |
|---|---|
| Not protected | Protect · Open in Finder |
| Project (protected / out of date) | Write .env · Preview .env · Open in Finder · Delete project |
| Project (no folder here) | Delete project (Write/Preview/Open disabled with the reason "no folder on this Mac") |
| Problem, orphaned | Protect this folder · Forget this folder · Open in Finder |
| Problem, unreadable | Open in Finder |
| Shared secret | none this ho |
| nothing | VAULT and New… only |

### Decision 8 — Status glyphs carry shape and the palette

| Status | Symbol | Token |
|---|---|---|
| Not protected | `circle` | inkSecondary |
| Protected | `checkmark.circle.fill` | inSync |
| Out of date | `exclamationmark.triangle.fill` | drift |
| Problem | `questionmark.circle` | drift |
| No folder here | `circle.dotted` | inkTertiary |

Tooltips say the status in the ten words. `GlyphState` and `DriftBadge` are
folded into `ProjectStatus`; `UnlinkedMarker` stays as the problem payload.

### Decision 9 — Project pages

The content column switches on the selection kind. `.project` keeps
`SecretList` + `SecretDetail` unchanged, with a new `ProjectHeader` strip
above the list: status word, drift count if any, abbreviated path or "No
folder on this Mac". `.candidate` shows `NotProtectedPage` (keyless preview
through `Materializer.ingest` on the worker, cached per selection, keys
listed with masked values, one Protect button). `.problem` shows
`ProblemPage` (plain-words explanation; verbs mirror the action column).
`.shared` shows `SharedSecretPage` (used-by list from `linkGraph`, read with
the scopes; a line saying editing arrives with linking). No modal is required
to see any state.

### Discovery (deferred to execution)

- Whether `NavigationSplitView`'s content/detail split survives the kind
  switch cleanly, or the `.candidate` / `.problem` / `.shared` pages take the
  combined content+detail width. Lean: combined width, via a single
  `Group` in the content column and an empty detail for those kinds.
- The exact words on the Problem page for an unreadable claim file.
- Whether `SecretList`'s navigation title stays the scope ID or moves into
  `ProjectHeader`.

## Phase 2 — Execute

Branch `project-first`. Three agent tasks, sequential: the model (tested,
headless), then the sidebar and pages, then the action column and the
retirement of the chooser's last traces.

- **[Ho-06.9-AT-01](../agent-tasks/Ho-06.9-AT-01.md) — Model: selection,
  project entries, candidates in the scan, launch selection.** No new views.
  Deletes the chooser's model code and tests; keeps the build green by
  removing the two view call sites.
- **[Ho-06.9-AT-02](../agent-tasks/Ho-06.9-AT-02.md) — Sidebar and pages.**
  `ProjectSidebar` replaces `ScopeSidebar`; `ProjectHeader`,
  `NotProtectedPage`, `ProblemPage`, `SharedSecretPage`; the window's
  kind switch; glyph tokens; ingest sheet and wizard finish-page words.
- **[Ho-06.9-AT-03](../agent-tasks/Ho-06.9-AT-03.md) — Contextual action
  column and New… menu.** Verbs by selection kind; VAULT group; the New…
  menu; dead code and strings gone; CI exclusions reconciled; the full
  rhythm.

### Testing and iteration approach

Per task, the standing rhythm: `swift package clean && swift test`
(never clean→build→test — the SwiftPM incremental-link bug after Core
changes) → `swift build -Xswiftc -warnings-as-errors` → `swift-format lint
--strict --recursive Sources Tests` → `swiftlint lint --strict` → coverage
≥90% with the `ci.yml` exclusion list reconciled (new View files join it with
justification; `IngestChooserSheet` and `ScopeSidebar` leave it). Every
status derivation, the selection cascade, the launch selection rule, and the
candidate cache live tested in `WorkshopModel` extensions over temp vaults
and injected roots; no test touches live user state or the Keychain.

### Done means

- The sidebar shows projects in four sections by status; every one of the
  five statuses has a row, a glyph, a page, and its verbs; nothing modal is
  needed to see where you are.
- A fresh launch with unprotected projects opens on the first of them; a
  Protect from any of its three entry points lands the project under
  Projects with the right glyph and selects it.
- The ingest chooser, `Ingest Project…`, and `Create Vault & Import` no
  longer exist; the first-run wizard lands in a window that opens on the
  first unprotected project.
- The action column shows only the selection's verbs plus VAULT and New….
- Every string this ho added or changed uses the ten words.
- Full rhythm green; coverage ≥90%; zero files under `Sources/SharibakoCore`
  or `Sources/SharibakoCLI` changed.
- The build session's sandbox walk: every frame read back and matching the
  drawing; the three jobs narrated from the frames.
